# 알고리즘 및 시간 복잡도 분석

입력 크기 `n`은 매 시뮬레이션 스텝에서 검사하는 주변 이동 에이전트 수다. 현재 구현은 공간 인덱스를 사용하지 않으므로 모든 동적 에이전트를 검사한다.

## Naive

현재 거리만 확인해 안전거리 안에서는 속도를 줄이고, 가까운 에이전트의 반대 방향으로 반발 벡터를 더한다. 미래 위치는 예측하지 않는다. 한 스텝에 에이전트 `n`명을 한 번 검사하므로 시간은 `O(n)`, 추가 공간은 `O(1)`이다.

## Velocity Obstacles

상대 위치와 상대 속도로 이차방정식의 충돌 진입 시간을 계산한다. 선호 속도·정지 속도와 3개 속력 × 24개 방향의 후보를 검사한다. 후보 수를 `K`라 하면 시간은 `O(Kn)`, 현재처럼 `K=74`가 고정이면 점근적으로 `O(n)`이지만 상수 비용이 Naive보다 크다. `candidate_checks`가 실제 평가량을 기록한다.

## ORCA

각 에이전트마다 속도 장애물 경계에서 ORCA 반평면을 만든다. 협조 에이전트는 회피 책임을 1/2씩, 비협조 작업자는 제어 로봇이 전부 부담한다. 선호 속도에서 시작해 위반한 반평면을 순서대로 2차원 선형계획으로 투영한다. 제약 생성은 `O(n)`, 현재 순차 선형계획의 최악 시간은 이전 제약을 다시 확인하므로 `O(n²)`이다. 일반적인 저차원 ORCA 구현은 평균적으로 더 낮은 비용을 보일 수 있으므로 최악 복잡도와 실측 Runtime을 구분한다.

## A*와 공간 분할

선반 회피는 세 알고리즘 공통의 격자 A*가 담당한다. 격자 정점 수를 `V`, 간선을 `E`라 하면 우선순위 큐 구현은 `O((V+E) log V)`다. 현재 동적 회피에는 k-d tree나 uniform grid가 없어서 모두 `n`을 직접 검사한다. 공간 분할을 추가하면 근접 후보 검색이 평균적으로 줄지만, 밀집 셀이나 최악 배치에서는 선형 검사가 남을 수 있다.

## 이론과 실측이 다른 이유

- VO의 후보 수와 조기 탈락 여부
- ORCA에서 실제로 위반한 제약 수
- Python/NumPy 호출 및 객체 생성 비용
- 목표 도달까지 필요한 전체 스텝 수
- 충돌로 인한 정지와 우회 경로

따라서 누적 계산 시간뿐 아니라 스텝당 평균·95백분위, 검사 횟수와 총 스텝 수를 함께 비교한다.
