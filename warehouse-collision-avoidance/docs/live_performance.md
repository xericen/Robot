# 실시간 비교 화면의 부하 개선

## 변경 범위

물리 스텝, 회피 함수, 충돌 판정과 원본 기록은 유지한다. 실시간 표시와 전달만 경량화했다.

- 동시 비교는2D로 시작한다.3D 보기를 선택하면 실제 Viser 뷰어를 연결하며2D로 돌아오면 iframe을 제거하고 서버3D 업데이트도 멈춘다.
- 실시간 웹3D 갱신은10Hz다. 물리 계산은 기존30Hz 고정 스텝을 사용한다.
- 화면 경로는 최대256개 점으로 표시하며 시작/현재 위치를 포함한다. 전체 물리 프레임·재생 기록·실험 CSV는 샘플을 줄이지 않는다.
- 매번3D 경로·위험 링 오브젝트를 다시 만들던 부분을 기존 핸들의 속성 갱신으로 바꿨다.
- 상태 파일은 현재 물리 프레임과 동적 상태만 기록한다. 정적 메타데이터는 버전별 파일로 분리하여 생성·초기화·완료 시 갱신한다.
- 프런트엔드는 metadata_version이 같으면 정적 정보의 반복 전송을 생략한다. 무거운 provenance/프레임 시간 표본/진단 로그는 완료 원본 기록에 유지한다.
- 새 세션의 status 조회는 명령/ACK 왕복 없이 원자적 상태 파일을 읽고 heartbeat만 갱신한다. 기존 버전의 실행 중 세션은 기존 제어 방식과 호환한다.
- 브라우저의 경로 문자열을 캐시하여 같은 프레임을 반복 계산하지 않는다.
- 실시간 대기는 기존 물리/표시 처리 시간에33ms를 무조건 더하던 방식에서 프레임 예산의 남은 시간만 대기하도록 변경했다. 물리 시간 dt는 바꾸지 않는다.

## 검증

관련 pytest57개 통과, 실제 프런트엔드 메서드를 사용하는 Node 검사4개 통과. 실제 단일 라이브 세션에서3D캔버스·2D 전환 시 iframe 제거·compact 응답·읽기 전용 상태 조회·Reset 메타데이터 갱신·3D 재연결을 확인했다.

기존 다른 라이브 세션3개가 동시 뷰어 한도를 사용 중이어서 새3개 세션의 브라우저 성능 비교는 수행하지 않았다. 해당 세션을 임의로 종료하지 않았다.3개 행의 경로 상한/캐시/선행 완료 로봇 유지/초기화는 실제 프런트엔드 메서드 회귀 검사로 검증했다.

측정 예: 동일한 기존5401프레임 실행의 한 상태를 사용한 직렬화 미세 벤치마크에서 반복 상태 파일은71134바이트→2120바이트(약97%감소),100회 평균 기록 비용은2.39ms→0.20ms였다. 이는 상태 봉투만의 값이며 HTTP 프레임 전달 전체나 실제 브라우저 FPS 개선율을 뜻하지 않는다. 원본 물리 샘플은 줄이지 않았다. 상세 수치는 results/newton/validation/delivery_9ce19b94/status_benchmark.json에 있다.

## 적용

실행 중이라면 먼저 **동시 비교 종료**를 누른 뒤 페이지를 새로고침하고 **Start · 3개 알고리즘 함께**를 다시 누른다. 초기화 시 적용되는3D 갱신 설정은 새 세션부터 반영된다.3D 화면3개는 GPU 자원을 사용하므로 부담이 큰 환경에서는 기본2D 보기로 비교한다.
