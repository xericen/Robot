# 세 알고리즘 동시 실행

## 사용 방법

1. 구현의 시뮬레이션 화면에서 Map1~Map6 중 하나를 선택한다.
2. **Start · 3개 알고리즘 함께**를 누른다.
3. Naive·VO·ORCA의 R0 세 대를 경로 요약과 세 개의 실제 Newton 3D/2D 화면에서 비교한다.
4. **함께 Pause / Resume / Reset**으로 제어한다. Reset 후에는 함께 Resume을 누른다.
5. 맵을 바꾸면 기존 세 세션을 종료하고 선택한 맵의 초기 상태로 세 로봇을 준비한다.
6. 기존 단일 실행은 **동시 비교 종료 → 선택 알고리즘만 Start**로 사용할 수 있다.

## 동일 조건과 시간

세 알고리즘은 맵·탐색기·시드·속도·안전거리·작업자 배치가 같은 초기 상태를 사용하며 시작 전에 scene_hash 일치를 확인한다. 비교 로봇끼리 서로 영향을 주지 않도록 독립 Newton 물리 환경을 사용한다. 하나의 Start 요청으로 세 환경을 준비한 후 공통 예약 시각에 실행한다.

CPU 부하에 따라 실제 처리 속도는 조금 다를 수 있다. 경로 요약과2D는 공통 물리 프레임을 표시하며 먼저 도착한 로봇은 목적지의 마지막 상태로 유지한다. 각3D 뷰어는 해당 환경의 실시간 상태를 표시한다.

## 작업자 왕복

기본으로 선택된 **모든 작업자 경로 횡단·왕복**은 기본 만남 조건을 기존의 시드 기반 Crossing/작업자 전용 조건으로 연결한다. worker-0뿐 아니라 worker-1~3도 실제 R0 전역 경로의 양쪽에서 출발하여 횡단한다. 목적지에 도착하면 기존 advance_patrol_goal 로직으로 반대편을 향해 되돌아간다.

작업자의 출발 시점은 명목 R0 도착 예상 시각과 시드로 정한다. 실행 초기에는 일부 작업자가 잠시 대기할 수 있다. 장애물을 통과하도록 만들거나 충돌 자체를 강제하지 않는다. 모든 작업자의 강체 접촉은 기존 Newton 충돌 판정에 포함된다. Head-On/좁은 교행 등 명시적으로 선택한 만남 조건과 혼합 인구는 그대로 유지한다. 정적 작업자 모드를 선택하면 작업자는 움직이지 않는다.

체크를 해제하면 기존 기본 배치의 순찰을 사용할 수 있다. 기존 배치의 바깥 순찰 작업자가 로봇을 만나지 않았던 것은 이동 경로의 차이였으며 worker-0에만 충돌을 허용하는 필터는 없었다.

## 제어·자원·결과 보존

- 각 세션의 polling과 제어는 클라이언트 대기열 및 서버 파일 잠금으로 직렬화한다.
- 새 맵을 준비하기 전에 종료된 세션의 뷰어 슬롯 반환을 기다린다.
- 세 개 중 초기화가 실패하면 이번 요청에서 만든 세션을 정리한다.
- 동시 비교를 종료하거나 페이지를 떠나면 해당 세션만 닫는다.
- 서버의 기존 동시 뷰어 한도4개를 유지한다. 다른 뷰어가 한도를 사용하면 안내 메시지가 표시된다.
- 기존 연구 CSV/JSON과 Pygame 자료는 유지한다. 완료된 새 실행은 기존 실행 ID별 보관 기능을 사용한다.

## 가벼운 표시

동시 실행은2D로 시작하며3D 보기 선택 시에만3개 Viser 화면을 연결한다.2D로 돌아가면3D iframe과 서버3D 갱신을 중단한다. 표시 경로는최대256점,3D 갱신은10Hz로 제한하며 물리30Hz·원본 프레임·실험 기록은 유지한다. [성능 개선 범위와 검증](live_performance.md)을 확인한다.

## 첫3D 장면부터 실행

시작 화면의 **3D · 첫 장면부터 보기**를 선택하고 Start를 누르면 세 뷰어의 실제 첫 장면이 준비될 때까지 이동하지 않는다. 실행 중3D 전환도 먼저 세 로봇을 멈추며 준비 후에 재개한다. 부모 화면·3D 처리 확인보다6프레임 이상 앞서면 물리 진행을 기다린다. [6개 맵 검증과 표시 진도 동기화](viewer_presentation_sync.md)를 참고한다.
